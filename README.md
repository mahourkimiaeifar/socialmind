# Socia Mind — سناریونویس فارسی با Django

نسخهٔ بازنویسی‌شدهٔ سایت Socia Mind با **Django خالص**، قالب‌های Django، CSS/JS ساده و SQLite.
رابط کاربری تیره و شیشه‌ای، راست‌به‌چپ و واکنش‌گراست و رفتار اصلی «سناریونویس» حفظ شده است:
گفتگوی فارسی، ساخت بریف، تأیید صریح بریف و فقط سپس تولید سناریو.

در این نسخه هیچ React/Next/Node، پایگاه‌دادهٔ برداری، سرویس بیرونی یا API عمومی برای نمایش
جزوه‌ها وجود ندارد. متن جزوه‌ها فقط در SQLite و برای مدیر قابل مشاهده است.

## ۱. پیش‌نیازها

- Windows PowerShell
- Python **۳.۱۲ یا بالاتر** (این نسخه با Python 3.14.8 تست شده است)
- دسترسی به یک سرویس سازگار با OpenAI (برای تولید واقعی سناریو)

وابستگی‌ها در `requirements.txt` آمده‌اند:

```text
Django==6.1.2
pypdf==6.21.4
```

## ۳. تنظیم فایل محیطی

```powershell
Copy-Item .env.example .env
notepad .env
```

نمونهٔ حداقلی:

```dotenv
DJANGO_SECRET_KEY=یک-مقدار-تصادفی-طولانی
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost

OPENAI_API_KEY=کلید-واقعی-فقط-روی-سرور
OPENAI_MODEL=gpt-5-mini
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_STYLE=responses
OPENAI_TIMEOUT=90
```

ساخت کلید تصادفی Django:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

نکات امنیتی:

- فایل `.env` واقعی هرگز نباید در Git قرار بگیرد. `.gitignore` آن را حذف می‌کند.
- کلید API فقط سمت سرور خوانده می‌شود؛ در HTML، JavaScript، پاسخ JSON یا لاگ چاپ نمی‌شود.
- برای سرویس‌های سازگار با Chat Completions مقدار `OPENAI_API_STYLE=chat` را بگذارید.
- اگر سرویس شما به پروکسی نیاز دارد، متغیرهای استاندارد `HTTPS_PROXY` / `HTTP_PROXY` را در
  همان ترمینالی تنظیم کنید که سرور Django را اجرا می‌کند.

## ۵. ورود جزوه‌های PDF

دستور ورود، متن، نام فایل و شمارهٔ صفحه را در SQLite ذخیره می‌کند و فایل‌های بدون متن را
گزارش می‌دهد؛ برای آن‌ها هیچ متنی حدس زده نمی‌شود.

مسیر پوشه در `.env` با `HANDOUTS_DIR` تنظیم می‌شود. اگر مسیر را در دستور بدهید، همان اولویت دارد:

```powershell
$env:PYTHONUTF8="1"
$env:PYTHONIOENCODING="utf-8"

# استفاده از HANDOUTS_DIR در .env
python manage.py import_handouts

# یا مسیر صریح
python manage.py import_handouts "C:\Users\iman\Documents\جزوه ها"
```

بررسی بدون تغییر پایگاه داده:

```powershell
python manage.py import_handouts --dry-run
```

رفتار ورود مجدد:

- فایل بدون تغییر دوباره وارد نمی‌شود (بدون رکورد تکراری).
- فایل تغییرکرده، نسخهٔ قبلی صفحات/بخش‌هایش حذف و نسخهٔ تازه جایگزین می‌شود.
- فایل خراب یا بدون متن باعث توقف کل ورود نمی‌شود و در گزارش پایانی می‌آید.

در این نسخه ۱۹ جزوه، ۲۷۴ صفحه و ۶۰۷ بخش قابل جستجو وارد شده‌اند و هیچ PDF کاملاً
اسکن‌شده‌ای پیدا نشد.

پس از ورود، لازم نیست دوباره دستور را بزنید: برنامه در **هر نوبت گفتگو** جزوه‌های
ذخیره‌شده را جست‌وجو می‌کند. اگر فایل‌های PDF را عوض کردید، همان دستور را دوباره اجرا
کنید تا نسخهٔ تغییرکرده جایگزین شود.

## ۶. ساخت کاربر مدیر

```powershell
python manage.py createsuperuser
```

در این نصب یک کاربر مدیر با نام `admin` ساخته شده و رمز آن فقط در فایل
`.admin-credentials.txt` (خارج از Git) قرار دارد. برای محیط واقعی رمز را عوض کنید
یا کاربر تازه بسازید.

نشانی مدیریت: `http://127.0.0.1:8000/admin/`

در بخش مدیر:

- فهرست جزوه‌ها با تعداد صفحه، تعداد صفحات دارای متن و تعداد بخش نمایش داده می‌شود.
- متن کامل صفحه و مسیر فایل در فهرست عمومی نمایش داده نمی‌شود.
- منابع بررسی‌شده در هر نوبت گفتگو و منابع روشیِ هر سناریو با **نام فایل + شمارهٔ صفحه**
  فقط برای مدیر ثبت می‌شوند.

## ۸. جریان استفاده

1. از داشبورد یا استودیو، «گفتگوی جدید» را بزنید.
2. سناریونویس در هر نوبت **یک سؤال روشن** می‌پرسد؛ سؤال بعدی به پاسخ قبلی وابسته است.
3. در همان نوبت، جزوه‌های ذخیره‌شده جست‌وجو می‌شوند. اگر پاسخ کوتاه یا کلی باشد و
   اصل روشی مرتبطی پیدا شود، **یک سؤال تکمیلی هدفمند** پرسیده می‌شود؛ مثلاً به‌جای
   تکرار سؤال کلی، دقیقاً دربارهٔ موقعیت روزمره یا بزرگ‌ترین نگرانی مخاطب می‌پرسد.
   اگر مدرک روشی پیدا نشود، سؤال از خود ساخته نمی‌شود و رفتار سادهٔ قبلی ادامه می‌یابد.
4. اگر پاسخ بخشی را نمی‌دانید، گزینه‌هایی پیشنهاد می‌شود. هیچ گزینه‌ای بدون انتخاب صریح
   شما در بریف ثبت نمی‌شود؛ موارد تأییدشده با برچسب «فرضیهٔ تأییدشده» نشان داده می‌شوند.
5. پس از کامل‌شدن ۹ بخش بریف، خلاصه نمایش داده می‌شود و دکمهٔ
   **«تأیید و ساخت سناریو»** فعال می‌شود.
6. تا کلیک روی این دکمه، هیچ درخواستی برای تولید سناریو فرستاده نمی‌شود.
7. خروجی شامل ایده/پیام اصلی، دغدغهٔ مخاطب، تکنیک و دلیل انتخاب، قلاب، صحنه‌ها با زمان‌بندی،
   تصویر/دوربین، متن گوینده، نوشتهٔ روی تصویر، دعوت به اقدام و کپشن پیشنهادی است.
8. با «درخواست اصلاح» یا فرم «ویرایش بریف» می‌توانید بخش‌ها را عوض کنید؛ بعد از ذخیره،
   بریف باید دوباره تأیید شود. سناریوهای قبلی برای مرجع می‌مانند و «نسخهٔ قبلی» علامت می‌خورند.
9. «گفتگوی جدید»، «تاریخچه»، «دیدن بریف» و «کپی سناریو» در همان صفحه در دسترس‌اند.

### محدودیت‌های پیام

مقادیر پیش‌فرض (قابل تغییر در `.env`):

- حداکثر ۱٬۵۰۰ نویسه برای هر پیام
- حداکثر ۴۰ پیام کاربر در هر گفتگو
- حداکثر ۱۰۰ پیام در هر گفتگو
- حداکثر ۲۰ گفتگو برای هر نشست
- فاصلهٔ ۲ ثانیه بین پیام‌ها
- حداکثر ۸ منبع روشی در هر تولید
- حداکثر ۵ بخش بررسی‌شده از جزوه‌ها در هر نوبت گفتگو (`HANDOUT_TURN_SOURCES`)
- جست‌وجوی هر نوبت با `HANDOUT_RETRIEVAL_PER_TURN=False` خاموش می‌شود

## ۹. اجرای تست‌ها

تست‌های عادی (بدون شبکه و بدون کلید واقعی):

```powershell
$env:PYTHONIOENCODING="utf-8"
$env:PYTHONUTF8="1"
python manage.py test -v 1
```

تست زندهٔ مدل (اختیاری، نیازمند شبکه و کلید معتبر):

```powershell
$env:RUN_LIVE_LLM_TESTS="1"
python manage.py test core.test_live_llm -v 2
```

اگر کلید تنظیم نشده باشد، تست زنده با پیام روشن skip می‌شود. اگر کلید نامعتبر باشد،
تست شکست می‌خورد و هیچ خروجی ساختگی جای آن نمی‌نشیند.

پوشش تست‌ها شامل این موارد است:

- جداسازی گفتگوهای نشست‌ها و کاربران
- ماندگاری پیام و بریف پس از بارگذاری مجدد
- جلوگیری از تولید پیش از تأیید و تولید تکراری
- خطای کلید نامعتبر و حفظ بریف/پیام کاربر
- محدودیت طول و تعداد پیام
- محافظت CSRF
- جست‌وجوی فارسی در جزوه‌ها و ورود بدون تکرار
- نبود نام فایل/متن خام در صفحات عمومی
- تولید mocked و ثبت منابع برای مدیر
- بازیابی جزوه‌ها در هر نوبت و ثبت منابع بررسی‌شده برای مدیر
- انتخاب سؤال تکمیلی هدفمند از میان اصول روشی، بدون افشای متن جزوه
- بازگشت به سؤال ساده وقتی مدرکی پیدا نمی‌شود

## ۱۱. حریم خصوصی و رفتار مدل

- متن جزوه‌ها، نام فایل‌ها و شمارهٔ صفحات در پاسخ کاربر نمایش داده نمی‌شود.
- سؤال تکمیلی از کتابخانهٔ ثابت انتخاب می‌شود؛ فقط «موضوع روشی» از جزوه تشخیص داده
  می‌شود و متن جزوه نقل نمی‌شود.
- پرامپت مدل فقط متن بخش‌های بازیابی‌شده را می‌گیرد، نه نام فایل یا مسیر.
- منابع بررسی‌شده در هر نوبت روی پیام کاربر (فقط برای مدیر) و منابع سناریو در جدول
  `ScenarioSource` با نام فایل و شمارهٔ صفحه ثبت می‌شوند.
- اگر مدرک روشی کافی پیدا نشود، برنامه به‌جای ساختن روش از خودش، پیام کمبود مدرک می‌دهد
  و سؤال تکمیلی می‌پرسد.
- برنامه ادعای قطعی پزشکی/حقوقی/مالی نمی‌سازد و تضمین وایرال‌شدن نمی‌دهد.
- گفتگوها به نشست مرورگر (و در صورت ورود، به کاربر) محدودند؛ کاربر مهمان فقط گفتگوهای
  بدون کاربر همان نشست را می‌بیند.
- همهٔ POSTها توکن CSRF دارند.

## ۱۲. عیب‌یابی

| نشانه | علت احتمالی | راه‌حل |
|---|---|---|
| «کلید API نامعتبر است...» | کلید اشتباه/منقضی یا مدل اشتباه | `OPENAI_API_KEY` و `OPENAI_MODEL` را در `.env` بررسی کنید؛ سرور را دوباره اجرا کنید |
| «ارتباط با سرویس مدل برقرار نشد» | قطع شبکه، پروکسی یا فایروال | اتصال، `HTTPS_PROXY` و دسترسی سرور را بررسی کنید |
| «مدرک روشی کافی پیدا نشد» | جست‌وجوی واژه‌ای به متن بریف نزدیک نشد | یک جزئیات واقعی به دغدغه/هدف اضافه کنید یا فرم بریف را کامل‌تر کنید |
| «کلید مدل تنظیم نشده» | `.env` خوانده نشده | فایل `.env` در ریشهٔ پروژه باشد و سرور دوباره اجرا شود |
| متن فارسی در PowerShell نامفهوم است | کدگذاری کنسول | `$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"` |
| پورت ۸۰۰۰ اشغال است | سرور قبلی باز است | `python manage.py runserver 127.0.0.1:8001` |
| PDF وارد نشد | فایل خراب یا اسکن‌شده بدون لایهٔ متن | گزارش دستور را ببینید؛ برای اسکن نیاز به OCR است که در این نسخه نیست |

نکتهٔ شبکه: در برخی شبکه‌ها دست‌دادن TLS پیش‌فرض Python با گروه پساکوانتومی
`X25519MLKEM768` قطع می‌شود. کلاینت مدل در `core/services/llm.py` گروه را به `X25519`
محدود می‌کند تا اتصال پایدار باشد.

## ۱۳. محدودیت‌های صادقانه

- تولید واقعی سناریو در این محیط با کلید موجود تأیید نشد: سرویس OpenAI برای کلید
  پیکربندی‌شده پاسخ `401 invalid_api_key` داد. کل مسیر برنامه با یک مدل محلی mocked
  (همان قرارداد Responses API) تست شد و خروجی، ذخیرهٔ منابع و نمایش آن درست بود.
- `ScenarioSource` منابع **بازیابی‌شده و تحویل‌شده به مدل** را ثبت می‌کند؛ اثبات
  جمله‌به‌جمله اینکه مدل از کدام منبع استفاده کرده نیست. برای ادعای دقیق‌تر به
  استناد ساخت‌یافته در خروجی مدل نیاز است.
- جست‌وجو واژه‌ای/آماری است و به پایگاه‌دادهٔ برداری وصل نیست؛ ممکن است بازنویسی‌های
  خیلی متفاوت را از دست بدهد. به همین دلیل سؤال تکمیلی فقط وقتی انتخاب می‌شود که
  موضوع روشی مرتبط در متن بازیابی‌شده دیده شود؛ در غیر این صورت سؤال سادهٔ قبلی می‌آید.
- «خواندن هر بار» به معنی جست‌وجو در ایندکس SQLite در هر نوبت است، نه دوباره‌خواندن
  فایل‌های PDF. اگر فایل‌ها را عوض کردید، `import_handouts` را دوباره اجرا کنید.
- SQLite و اجرای تک‌پروسه‌ای برای استفادهٔ کوچک مناسب است؛ برای ترافیک بالا به
  PostgreSQL و صف پس‌زمینه نیاز است.
- PDFهای اسکن‌شده OCR نمی‌شوند؛ فقط شناسایی و گزارش می‌شوند.
- اتصال واقعی به اینستاگرام، انتشار خودکار، آمار پیج، تقویم محتوا و بخش‌های مشابه
  در این نسخه فعال نیستند و با برچسب «به‌زودی» غیرفعال شده‌اند.
- تنظیمات پیش‌فرض برای توسعه است (`DEBUG=True`). برای استقرار واقعی باید
  `DEBUG=False`، `ALLOWED_HOSTS`، `CSRF_TRUSTED_ORIGINS`، HTTPS، `SECRET_KEY` تازه
  و سرور WSGI/ASGI مناسب تنظیم شود.
